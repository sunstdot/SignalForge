# 今日 AI 情报机会与创投产品雷达数据隔离设计

## 目标

- 「今日 AI 情报机会」只展示确实存在商业机会或研发机会数据的日期。
- 创投产品雷达只使用 `data/venture_radar/`，不再向「今日 AI 情报」使用的 `data/content/` 写入数据。
- 清理已混入 `data/content/` 的创投产品雷达条目，同时保留普通情报数据和 `data/venture_radar/` 原始报告。

## 根因

侧栏目前在所有日更页面复用 `/api/dates`。该接口根据 `data/content/*.json` 生成日期列表，不检查对应日期的 `data/opportunities/` 或 `data/rdev_opportunities/` 是否包含机会，因此空机会日期仍会出现在「今日 AI 情报机会」中。

创投产品雷达导入流程又同时执行两次持久化：把标准化条目写入 `data/content/`，并把原始报告归档到 `data/venture_radar/`。这条双写路径让创投报告中的产品发布日期和融资日期进入日更情报日期列表，造成两个栏目的缓存和归档互相污染。

## 设计

### 1. 机会日期使用独立索引语义

存储服务新增机会日期查询。它读取 `data/opportunities/*.json` 和 `data/rdev_opportunities/*.json` 的日期并取并集，但只保留至少满足以下一个条件的日期：

- 商业机会缓存中的 `opportunities` 是非空列表；
- 研发机会缓存中的 `solutions` 是非空列表。

新增只读 API 返回这个倒序日期列表。侧栏处于 `/daily-opportunities/:date` 时使用机会日期 API；其他日更情报页面继续使用 `/api/dates`。菜单中的「今日 AI 情报机会」链接使用最新机会日期，避免跳到只有简报、没有机会数据的日期。

空文件、无目标字段、目标字段不是列表或列表为空，都视为该类机会无数据。单侧有数据时日期仍然展示。

### 2. 创投产品雷达只保留专用归档

创投雷达运行和导入完成后，只调用报告归档服务：

```text
外部 venture-product-radar JSON
  -> 校验报告
  -> data/venture_radar/reports/<report-id>.json
  -> data/venture_radar/index.json
```

导入流程不再调用 `store_content_items`，也不再把创投公司、产品、融资和信号转换后写入 `data/content/`。现有创投雷达周列表、周聚合和报告读取接口继续以 `data/venture_radar/` 为唯一数据源。

CLI 和后台任务的成功结果改为描述已归档报告，不再声称导入了通用情报条目。

### 3. 历史数据清理与防御

对现有 `data/content/*.json` 做一次定向清理：

- 只删除 `metadata.origin == "venture-product-radar"` 的条目；
- 保留同一文件中的其他来源条目及其原有顺序和内容；
- 清理后列表为空时删除该日期文件；
- 不修改 `data/venture_radar/`、简报、机会或研发机会缓存。

通用日更日期判定同时排除 `last30days` 和 `venture-product-radar` 来源。这样即使旧文件残留或未来发生异常写入，纯辅助数据日期也不会再出现在「今日 AI 情报」归档中；混合文件只要含普通日更条目仍会保留。

## 错误处理

- 日期查询沿用文件型存储的现有行为；缺失目录或无匹配缓存时返回空列表。
- 已存在但无法解析的缓存文件不在本次范围内静默修复，保持现有错误可见性。
- 创投报告仍由现有 schema 校验拒绝无效 JSON，不回退到通用内容库。

## 测试与验收

后端回归测试覆盖：

- 商业机会和研发机会都为空的日期不返回；
- 任意一类机会非空的日期返回，且结果倒序、无重复；
- 纯创投雷达内容日期不进入通用日期列表，混合日期仍保留；
- 创投雷达 direct 与 Wingsbot 路径只写专用归档，不调用通用内容存储；
- 定向清理仅移除创投条目，并删除清理后为空的日期文件。

前端回归测试覆盖：

- 「今日 AI 情报机会」路由请求机会日期 API，并用最新机会日期生成菜单链接；
- 普通情报路由继续请求通用日期 API；
- 创投雷达路由继续使用周归档 API，不与两种日更日期列表混用。

验收时运行相关后端测试、前端 Node 测试和前端构建，并检查清理后的 `data/content/` 中不再存在 `venture-product-radar` 来源条目。

## 范围边界

本次不调整创投雷达报告结构、周聚合算法、机会生成逻辑或页面视觉样式，也不删除任何 `data/venture_radar/` 报告。
