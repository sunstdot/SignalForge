# SignalForge 双轨信号雷达 — 设计文档

**日期：** 2026-10-10
**状态：** 已确认（Phase 1 实施时保留 Anthropic RSS 作为兜底）

## 1. 背景与目标

SignalForge 当前是一个"AI 情报阅读器"：每天从 60+ 个二手源（RSS/Newsletter/公众号）抓取内容，生成平铺日报。使用中的核心问题：

1. **内容太多、质量参差**：读完要 1 小时以上，公司博客尤甚——Meta/Google 的 PR 文章淹没技术内容，Anthropic 的技术文章拉不到（当前依赖 wingsbot agent，不稳定）。
2. **永远慢几步**：一手信号（X / Reddit / Hacker News）只在"情报搜索"（last30days pull 模式）里存在，没有接入每日流水线（push）。
3. **看不到趋势、落不了地**：没有信号打分、没有跨源聚类，用户只能人肉筛；实验想法池、实验直播场、创投雷达等"记录/追踪"类功能与真实诉求（发现 + 灵感）不匹配，长期吃灰。

**目标**：把系统从"日报阅读器"重构为"双轨信号雷达"——上游优先 + 信号打分 + 跨源聚类 + 双轨（灵感 / 执行）输出，让用户每天 **10 分钟** 扫完真正值得看的高信号条目，并能就感兴趣的点做深度盘点。

## 2. 范围

**本次包含：**

- 公司博客优化器（Anthropic 确定性抓取 + 三桶分类 + 跨博客去重）。
- last30days watchlist 从"搜索模式"接入每日流水线（上游 push）。
- 新增信号打分与跨源聚类层（含数据模型扩展）。
- 双轨输出：灵感雷达 + 执行雷达，及"今日信号"视图。
- 行为反馈闭环（收藏 / 点击 / 忽略 → 微调权重）。
- 功能取舍：砍实验直播场 / 实验想法池 / 创投雷达，情报搜索降级保留。

**本次不包含：**

- 删除或停用任何现有数据源（**源全部保留**，由打分层过滤，而非采集阶段砍源）。
- 机器学习排序（等行为反馈数据量足够后再评估）。
- 周度趋势复盘（列为 Phase 4 可选项）。
- 视频生成 / wiki / share 页面的改动。
- 从零实现 X/Reddit/HN 爬虫（复用现有 last30days 引擎）。

## 3. 核心方案

### 3.1 重定位与数据流

```
[上游] last30days watchlist 每日定时跑（X/Reddit/HN/YouTube，带互动数据）
                  +
[精选公司博客] 公司博客优化器（高权威技术流 + 产品发布信号）
                  +
[其余二手源] 现有 RSS/公众号等全部保留（降级为"背景/深读"）
                  ↓
        统一入库（现有 content item + 新增 signal 字段）
                  ↓
      【信号打分 + 去重 + 跨源聚类】（新增层，系统"脑子"）
                  ↓
   ┌───────────────┴───────────────┐
   轨道 1 · 灵感雷达          轨道 2 · 执行雷达
   （新项目/新玩法/趋势）      （论文/仓库/工具/技术文章）
                  ↓
    "今日信号" 10 分钟视图 + 深读钩子 + 收藏/笔记
```

### 3.2 双轨定义

- **灵感轨（inspiration）**：新项目、新玩法、趋势、产品/模型发布、融资、Show HN、ProductHunt 产品、X 上的产品思路。面向"未来做什么"。
- **执行轨（execution）**：论文、GitHub 仓库、工具、benchmark、技术教程、官方技术文章。面向"把手上的事做得更好"。

## 4. 采集层

### 4.1 公司博客优化器（Phase 1 最高优先级）

**问题**：公司博客是质量差的主要来源。实测 2026-09-23 入库的公司博客条目约 2/3 是 PR/公司新闻，真正有用的技术内容被淹没；Anthropic 一条都没有。

**Anthropic 确定性抓取器**（替换现有 wingsbot agent 方案）：

- 实测 `https://www.anthropic.com/engineering` 与 `/research` 为服务端渲染 HTML（HTTP 200，约 139KB），可直接解析出文章 slug、标题、日期，结构为：
  ```html
  <a class="...cardLink" href="/engineering/{slug}">
    ...<h3 class="headline-4">{标题}</h3>
    ...<time dateTime="{YYYY-MM-DD}">...
  </a>
  ```
- 新 fetcher 直接 HTTP GET + 正则/HTML 解析，产出 `source_type=anthropic_blog`、`authority=10` 的条目，进执行轨。
- 替代 `anthropic_blog_fetcher.py` 中依赖 wingsbot 的 `fetch_anthropic_technical_articles`（保留旧函数签名）；保留原 Anthropic RSS 作为直抓失败的兜底，直抓成功则优先使用带正文的直抓条目。

**三桶分类器**（针对所有公司博客条目）：

| 桶 | 定义 | 处理 |
|---|---|---|
| 🛠 技术/工程 | 教程、开源、系统设计、research、benchmark | 执行轨，高权威 |
| 🚀 产品/模型发布 | 新模型、新能力、API 变更、新工具 | 灵感轨，高信号 |
| 🏢 公司新闻 | 合作/融资/招聘/政策/活动 | 降权折叠，默认不占今日信号 |

实现：先关键词 + URL 路径粗分（免费），LLM 仅对模糊条目做一次精分（量少）。

**跨博客去重**：同一发布（如某模型同时上 OpenAI+Google+Meta）只保留一篇 canonical，其余折叠为"同源报道 ×N"。

### 4.2 last30days watchlist 上游接入（Phase 1）

复用仓库已集成的 last30days 引擎（`last30days_importer.py` 已能把其 raw v3 JSON 转成带 engagement 与 0-10 分数的 content item）。

- Phase 1 在 `backend/config/collector.yaml` 配置 `sources.watchlist.topics`（关键词）与可选的 `accounts`（指定 X handle）。复用现有 `pnpm daily` 调度，每天按话题调用已集成的 last30days/Wingsbot 引擎；**不单独依赖 last30days skill 内置 watch add 调度器**。
- X 账号查询在 prompt 中要求添加 `--x-handle`，同时保留 Reddit/HN/Web 检索；免费 X 能否返回结果取决于本机服务/凭据，不能保证。
- 仅收录有明确发表日期的近三日帖子：保留原发布时间，记录当日发现日期，并限制相同帖子重复入榜；手工情报搜索的原有导入语义不变。
- 产出由现有 importer 入库，标记 `source_type` 为 `x`/`reddit`/`hn`/`youtube` 等。

### 4.3 其余二手源

**全部保留**，不删除配置。RSS/公众号/Newsletter 等继续采集，但由打分层决定是否浮出"今日信号"。用户可随时在"全部内容"里浏览任何源的条目。

## 5. 信号打分与聚类层

### 5.1 打分哲学

分数衡量"值不值得**现在**花用户 10 分钟看"，不是客观重要性。

### 5.2 六个维度

| 维度 | 数据来源 | 说明 |
|---|---|---|
| 速度 velocity | 发布时间 + 热度变化率 | 正在涨 > 已凉 |
| 社区验证 engagement | HN points/comments、Reddit upvotes、X likes/RT、PH votes | 独立人群投票 |
| 来源权威 authority | 静态权重表 | 一手技术 > KOL > 普通 > 转载 |
| 主题相关 relevance | 关键词 + LLM 分类一次 | 命中灵感/执行主题 |
| 跨源确认 cross_source | 语义/标题聚类 | 多源共振 = 真趋势 |
| 新颖性 novelty | 与已见内容去重 | 首现加分，重复降权 |

### 5.3 组合公式

```
score = w1·velocity + w2·engagement + w3·authority + w4·relevance + w5·cross_source + w6·novelty
```

**权重初始化**：Phase 2 先取等权（w1..w6 = 1），仅 velocity / cross_source 给 1.5 倍初始权重（它们是趋势的最强信号），后续由行为反馈闭环自动调参，不做手工调参。

**关键设计：**

- **跨源归一化**：每项先做源内百分位（"这条在 HN 今天帖子里排前 5%"），再进公式，避免 HN 分数霸榜。
- **跨源聚类 = 趋势检测**：同一件事 ≥2 个独立源出现时，簇内条目乘性加分，簇自动成为"今日趋势"头条。
- **行为反馈**：收藏/点击/忽略是"值得看"的 ground truth，定期微调各源与主题权重；只学"对哪类信号敏感"，不锁死到具体项目。
- **LLM 职责**：只做分类（灵感/执行）+ 写一句 so-what，不参与原始打分。

### 5.4 数据模型扩展（向后兼容）

在现有 content item 字段（`id/source/source_type/title/url/original_content/raw_text/relevance_score/category/published_date/created_at`）基础上新增：

```yaml
signal:                       # 新增对象，缺省时按 legacy 处理
  velocity: 0-10
  engagement: 0-10
  authority: 0-10
  relevance: 0-10
  novelty: 0-10
  cross_source: 0-10
  final_score: 0-10
  track: "inspiration" | "execution"
  cluster_id: str | null
  why: "3源共振·2小时冲上HN前10·命中agent主题"   # 可解释理由
```

现有 `relevance_score` 保留，作为 legacy 排序兜底；`final_score` 生效后优先使用。

## 6. 双轨输出与 UI

### 6.1 今日信号（默认首页，Phase 3）

- 只显示打分最高的 **10-15 条**，按"灵感 / 执行"两个 tab 分组。
- 每条一行：标题 + 一句 so-what + "为什么上榜"徽标（如 `3源共振` `🔥急速上升` `命中agent`）。
- 趋势簇置顶，标注"今天真正的趋势，不是单篇爆文"。
- 10 分钟扫完。

### 6.2 深读钩子

点开一条 → 展开全文 + 同簇内其它来源讨论 + 相关链接，支持"一键深挖"（复用 last30days 引擎针对该条再查一轮）。

### 6.3 收藏 / 笔记

每条信号上的极简"⭐收藏 + 一句话笔记"，替代原实验想法池（不做状态/假设/结果表单）。收藏与笔记数据同时是反馈闭环的信号源。

## 7. 功能取舍

| 功能 | 处理 |
|---|---|
| 实验直播场 / 实验想法池 | 砍（替换为信号上的收藏 + 一句话笔记） |
| 创投雷达 | 砍（非主诉求） |
| 情报搜索 | 降级保留（引擎与新上游同源，UI 收进"深挖"入口） |
| 机会分析 | 并入灵感轨（变成每条灵感信号的"可玩方向"一句话） |
| 60+ 二手源 | **不砍**，全部保留，由打分层过滤 |
| 视频生成 / wiki / share | 不动，不在本次范围 |

## 8. 落地节奏（YAGNI）

- **Phase 1（先出效果）**：公司博客优化器（Anthropic 抓取 + 三桶分类 + 去重）+ last30days watchlist 每日接入 + 简报生成器输出"双轨 + 今日信号 10-15 条 + so-what 一句"。解决"慢 + 噪音"，UI 可先复用现有简报页。
- **Phase 2**：信号打分 + 跨源聚类（第 5 节数据模型与公式）。
- **Phase 3**：双轨 UI + 收藏/笔记 + 行为反馈闭环。
- **Phase 4（可选）**：周度趋势复盘。

## 9. 测试

- Anthropic 抓取器：对抓取结果断言标题/链接/日期非空、URL 均在 `anthropic.com`、按日期降序、排除招聘/政策等非技术条目。
- 三桶分类器：覆盖技术/产品发布/公司新闻三类样本，验证分类与降权。
- 跨博客去重：同一发布的多个来源折叠为一条 canonical。
- 打分与归一化：跨源百分位计算正确；不同源的分数可比（HN 高分不霸榜）。
- 聚类：同一事件跨源出现时 cluster_id 一致，簇内条目获得加分。
- last30days 入库：watchlist 产出能走现有 importer 正常入库，字段完整。
- 双轨输出：灵感/执行分类正确，so-what 一句非空，今日信号 ≤15 条。

## 10. 成功标准

- 每天"今日信号"10 分钟内可扫完，且覆盖当天的真趋势（跨源共振项）。
- Anthropic 技术文章稳定出现在执行轨（不再依赖 agent）。
- 公司博客的 PR/公司新闻默认不占据今日信号。
- 一手源（X/Reddit/HN）内容进入每日流水线，不再只能靠搜索获取。
- 一个源都不删，冷门源内容仍可浏览。
- 行为反馈让雷达随时间更贴合用户兴趣，且不锁死到单一项目。

## 11. 风险与开放问题

- **last30days watchlist 能力验证**：是否支持按账号关注需在 Phase 1 实现时确认；不支持则退化为关键词 topic 列表。
- **X 获取稳定性**：免费方案（RSSHub/第三方桥）可能失效，作为"尽力而为"层，失败不影响整体流水线。
- **聚类实现方式**：优先用标题归一化 + 实体匹配（轻量）；语义 embedding 作为后备，需评估额外依赖成本。
- **三桶分类准确性**：关键词粗分可能误判，需 LLM 精分兜底，并允许用户手动改桶（反馈闭环的一部分）。
